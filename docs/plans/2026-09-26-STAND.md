## Arbeitsweise, die sich bewährt hat

Je Block ein Implementier-Agent (Trainer für Trainer: Audit lesen → Block schreiben → jede Zahl mit Wolfram → per Skript einsetzen, CRLF erhalten → Gates → Screenshot L5/L6 ansehen → Commit), danach ein Prüf-Agent (rechnet nach, prüft Rubrik, läuft Gates), Befunde werden direkt behoben und als „Review"-Commit nachgezogen. Der Prüf-Agent kann parallel zum nächsten Implementier-Block laufen, weil er nur liest.

Prüfschleife:
```
python tests/level_check.py --strict trainer/<datei>.html
python tests/lehrplan_check.py --strict trainer/<datei>.html
python -m http.server 8765        # einmal je Sitzung
python tests/katex_check.py trainer/<datei>.html
python -m pytest tests/test_trainer.py -k "<stem>" -q
python tests/bild.py trainer/<datei>.html --level 5   # PNG ansehen!
```

## Befunde aus den Reviews (bereits behoben)

- Einfache statt doppelte Backslashes in JS-Strings lassen KaTeX-Befehle verschwinden („cdot"), `katex_check` sah das nicht → jetzt harter Fehler im Level-Gate.
- Negative Koordinaten nach `|` in `{…}` setzen, sonst setzt KaTeX ein binäres Minus.
- Aufgaben ohne Zeichnung brauchen eindeutigen Bezug („Höhe auf die Grundseite").
