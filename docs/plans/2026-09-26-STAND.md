## Arbeitsweise, die sich bewährt hat

Je Block (5–7 Trainer) ein Implementier-Agent mit vollem Auftragstext (Rubrik, TH-Kapitel, Trainer-Abgrenzung, Prüfschleife), der Trainer für Trainer arbeitet: Audit lesen → Block schreiben → jede Zahl mit Wolfram → per Python-Skript einsetzen (CRLF/LF je Datei erhalten, nie Bash-Heredoc) → Gates → Screenshot L5/L6 ansehen → Commit nur eigener Dateien. Danach ein Prüf-Agent (rechnet nach, prüft Rubrik, Dubletten, MC-Längen, Tipps, läuft Gates); Befunde behebt derselbe Implementier-Agent per SendMessage (Kontext intakt) oder ein Fix-Agent. Prüfer und nächster Implementierer laufen parallel, weil der Prüfer nur liest. Parallel arbeitende Implementierer brauchen **disjunkte Dateilisten** (auch Kriterien-Dateien), sonst Kommit-Kollisionen.

Prüfschleife:
```
python tests/level_check.py --strict trainer/<datei>.html   # 0 Fehler, Warnungen beheben
python tests/lehrplan_check.py --strict trainer/<datei>.html
python -m http.server 8765                                  # einmal je Sitzung
python tests/katex_check.py trainer/<datei>.html
python -m pytest tests/test_trainer.py -k "<stem>" -q
python tests/bild.py trainer/<datei>.html --level 5         # PNG ansehen!
```

## Bewusst offen gelassen

- KOLLAPS L1/L2 bzw. L2/L3 in einigen Trainern (Stufe 1–3 werden nur entdoppelt, nicht neu geschrieben).
- Negative Koordinaten nach `|` in `{…}`: in neuen Blöcken teils so gesetzt, im Bestand nicht durchgängig; KaTeX rendert beides lesbar.
- Bestand-Muster `„…\"` (gerades Schlusszeichen) in L1–L3 vieler Trainer.
- Index-Namen der Umzug-Trainer („Strahlensätze", „Ähnlichkeit & zentr. Streckung") unverändert.
